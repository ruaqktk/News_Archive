# 단독·기획 선별 기준

매일 아침 같은 기준으로 판단하기 위한 문서입니다. 기계적으로 적용할 수 있는 부분은 `config/classification-rules.json`에 규칙으로 두고, `scripts/triage.mjs`가 **제목만 보고** 먼저 판정합니다. Claude는 규칙으로 판정되지 않은 "검토 필요" 기사만 직접 판단합니다.

## 1. 정의

- **단독(exclusive)**: 언론사가 제목에 `[단독]`, `〈단독〉`, `[단독 인터뷰]`처럼 **명시적으로 단독 표기**를 한 기사. 표기가 없으면 아무리 특종성 기사여도 단독으로 보지 않는다. "단독주택", "단독 선두" 같은 일반 단어는 해당하지 않는다.
- **기획(feature)**: 언론사가 **기획·연재·탐사·르포로 편성한 취재 보도 기사**. 기자가 취재해 쓴 보도여야 하며, 개인 의견을 담은 글(칼럼·사설)이나 협찬·홍보성 특집은 기획이 아니다.
- 둘 다 해당하면 **단독**으로 분류하고, 근거에 기획명을 함께 적는다.

## 2. 제목 판정 순서 (`triage.mjs`)

제목에서 괄호 문패(`[ ]`, `〈 〉`, `< >`, `【 】`)를 뽑은 뒤 아래 순서대로 적용합니다. 먼저 걸리는 규칙이 판정입니다.

| 순서 | 조건 | 판정 |
|---|---|---|
| 1 | 단독 표기 문패 (`exclusiveTags`) | 단독 |
| 2 | 언론사별 **연재 등록부**(`seriesRegistry`)에 있는 문패 | 등록된 판정(기획 또는 제외) |
| 3 | 제외 문패: 사설·칼럼·시론·기고·기자수첩·특파원·코너명·운세·날씨·사진·인사·부고·방송 안내 등 (`excludeTagWords`, `excludeTagExact`) | 제외 |
| 4 | 기획 문패: 기획·심층·탐사·르포·연재·시리즈·집중점검 등이 들어간 문패 (`featureTagWords`) | 기획 |
| 5 | 필자 이름으로 시작하는 문패 (예: `[김철중의 생로병사]`, `[정덕현의 그 영화 이 대사]`) | 제외 (개인 칼럼) |
| 6 | 위에 해당하지 않는 문패, 또는 문패 없이 연재 번호(①, `<2>`, `(上)`)만 있는 제목 | **검토 필요** |
| 7 | 문패도 연재 번호도 없는 제목 | 제외 |

자동 판정은 그대로 따르고 다시 검토하지 않는다. 판정이 틀린 사례를 발견하면 규칙 파일을 고친다(아래 4번).

## 3. "검토 필요" 판단 기준 (Claude)

본문 앞부분(`inspect-day.mjs bodies`)을 보고 아래 질문에 답한다.

1. 기자가 직접 취재한 **보도 기사**인가? 외부 필자의 글, 의견·에세이, 단순 정보 코너라면 → 제외
2. 언론사가 **여러 회에 걸쳐 편성한 시리즈**이거나, 한 주제를 여러 꼭지로 묶은 **기획 패키지**인가? (문패 아래 같은 날 여러 기사, 회차 번호, 본문의 "기획", "연재", "시리즈" 언급) → 기획
3. 기업·기관과의 **공동 캠페인, 협찬, 홍보성** 특집인가? (본문에 "공동 캠페인", "후원", 기업 홍보 위주) → 제외
4. 정기 인터뷰 코너라도 언론사 기획 연재(회차가 있고 특정 주제를 다룸)면 기획, 매일 돌아가는 일반 인터뷰 코너면 제외
5. 그래도 판단이 서지 않으면 **포함하지 않는다.**

## 4. 연재 등록부 갱신

검토 필요로 판단한 문패는 결과와 상관없이 `config/classification-rules.json`의 `seriesRegistry.<언론사ID>`에 기록한다. 그러면 다음부터 같은 문패는 자동 판정된다.

```json
"segye": {
  "이해충돌에 길 잃은 국가정책": { "decision": "feature", "note": "세계일보 분석 기획" }
}
```

- 키는 문패 텍스트 그대로(필자명 `/` 뒤는 빼고). 문패가 `심층기획-○○`처럼 바뀌는 앞부분이면 앞부분만 등록해도 된다.
- 언론사 전체에 공통인 코너명(예: 새 운세 코너명)이면 `excludeTagWords`에 추가한다.
- 등록 후 `npm test`로 기존 판정이 깨지지 않았는지 확인한다.

## 5. 요약 작성

기사마다 두 가지를 쓴다. 모두 원문 문장을 옮기지 않고 **자신의 말로** 쓰며, 직접 인용은 넣지 않는다. 추측이나 평가를 덧붙이지 않는다.

**카드 요약 (`summary`)**: 1~2문장, 120자 안팎. 무엇이 새로 밝혀졌는지 한눈에.

**상세 요약 (`detail`)**: 기사를 처음 보는 사람이 이 분야의 맥락까지 파악할 수 있게.
- `background` (배경, 2~4문장): 이 기사를 이해하는 데 필요한 사전 맥락. 제도·사건의 경위, 관련 수치의 의미 등. 일반적으로 알려진 사실만 쓰고, 확실하지 않은 내용은 쓰지 않는다.
- `points` (핵심 정리, 3~5개): 기사가 전하는 사실을 항목별로 한 문장씩. 수치·주체·시점을 구체적으로 쓰되, 수치가 든 문장도 원문 어순을 그대로 따르지 말고 다시 짜서 쓴다.
- `significance` (왜 중요한가, 2~3문장): 이 보도가 갖는 의미, 쟁점, 앞으로 지켜볼 점. 기사에서 제기된 쟁점이나 반론을 중심으로.
- `terms` (용어 풀이, 선택 0~3개): 일반 독자에게 낯선 용어만. `{ "term": "LTA", "description": "…" }`

전체 상세 요약은 원문보다 충분히 짧게(대략 600자 이내) 유지한다.

## 6. 근거(`evidence`)

`triage.mjs`가 만든 근거를 그대로 쓴다. 검토로 판단한 기사는 `세계일보 [내 일을 만드는 청년들] 연재 인터뷰 14회(본문 확인)`처럼 한 줄로 적는다.

## 7. 분야(`section`)

모든 선정 기사에 아래 7개 중 하나를 붙인다. 언론사마다 섹션 이름이 달라서 네이버 뉴스 분류 기준으로 통일한다.

`정치` · `경제` · `사회` · `생활·문화` · `세계` · `IT·과학` · `스포츠`

1. 수집기가 네이버 기사 페이지의 분류를 읽어 `sectionHint`로 넣는다(네이버 "생활"·"문화"·"연예" → 생활·문화, "IT"·"과학" → IT·과학).
2. 네이버 분류가 없으면 언론사 원문 주소의 섹션 경로(조선·동아·한겨레·매경 등)로 정한다.
3. 둘 다 없으면 기사 내용으로 판단한다. 기준: 정부·국회·선거·외교안보·북한 → 정치 / 거시경제·산업·기업·금융·부동산·노동시장 → 경제 / 사건사고·법원·교육·복지·의료·환경·지역 → 사회 / 문화·예술·콘텐츠·여행·종교 → 생활·문화 / 해외 정세 → 세계 / 기술·과학 연구 → IT·과학.
4. `triage.mjs --selections` 초안에 `sectionHint`가 미리 채워진다. 힌트가 기사 내용과 명백히 다르면 고친다. 비어 있으면 `build-run.mjs`가 멈추므로 반드시 채운다.
